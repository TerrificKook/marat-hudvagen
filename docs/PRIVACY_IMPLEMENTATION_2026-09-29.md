В исходной финальной версии нет форм приёма заявок и аналитики. Убрано уведомление «О данных», записывавшее только собственное подтверждение в localStorage. Обновлено техническое пояснение site-final/privacy.html. Старую локальную отметку новый код не читает и не использует.

Публичный корень и SEO-адреса пересобраны по существующему CNAME www.hudwagen.ru вместо старого GitHub Pages URL. Исправлен генератор notes/generate-public-root.cjs, чтобы следующая сборка не возвращала старый адрес. DNS и перенаправление hudwagen.ru на www.hudwagen.ru не настроены этой правкой: проверить при переезде. Сохранены концепты, дизайн, контакты Марата, тарифы и содержание. notes/check-package.cjs проходит.

## Границы готовности

От маминого ИП уведомление РКН НЕ подавалось. Этот сайт не относится к маминому ИП автоматически. Установить реального исполнителя и оператора Hudwagen, его реквизиты и адрес, кто принимает обращения, где хранятся переписка и заказы, основания и сроки обработки, доступы и требуемое уведомление. Публичная страница о данных описывает код, но не заменяет полную юридическую политику без этих фактов.

Не менялись права на домен, доступы, DNS и хостинг. Данные не подавались в РКН. Почта, логи, базы заказов и исторические данные аналитических кабинетов не проверялись. Российский хостинг сам по себе не закрывает работу с обращениями.

## Публичный пакет и REG.RU

`python3 tools/package_public.py` создаёт dist-regru только из публичных файлов. Не загружать весь репозиторий, включая .git, docs, notes, исследования и клиентские материалы.

Workflow публикации в этой ветке НЕ подключён. Референсная реализация: TerrificKook/dinarcraft, коммит 652827571b619ab428b0735fa0d4a58b4b7b2c0e, файл .github/workflows/deploy-regru.yml. Она подготовлена для отдельного этапа настройки. Нужны подтверждённые SSH/rsync, адрес сервера, пользователь, порт, отдельный каталог, приватный ключ в GitHub Secrets и проверенный ключ сервера. Не отключать проверку SSH-ключа и не публиковать секреты.

Порядок: проверить существующую услугу «Хостинг - 1»; подтвердить размещение услуги/почты/логов/копий в РФ; создать отдельный пустой каталог; загрузить пакет и проверить страницы, контакты и HTTPS; сохранить DNS-зону и изменить только нужные A/AAAA/CNAME; сохранить почтовые записи и подтверждения поисковых кабинетов; затем отключить старые GitHub Pages и их деплой. Автоматизацию после push включать после успешной ручной проверки. В GitHub не должны попадать клиентские данные и серверные журналы.

Перенос регистрации домена, новая CMS, база MySQL и отдельный VPS ради этих статических страниц не нужны. Это техническая правка, не заключение о полном соблюдении 152-ФЗ.
